# ILA 3-1: Applying the Four Pillars of OOP

## Sari-Sari Store Inventory System

### 1. Encapsulation
Encapsulation can be applied in this scenario by creating a class that encapsulates the 5 main variables in one unit along with a function like editProduct(). Through encapsulation, editing variables is controlled and it also prevents these variables to scatter around. For example, when editing the names of the products, it is not necessary to make another string of code to change the variables of the other function.

### 2. Abstraction
In this scenario, abstraction is applied by hiding the complex processes behind the code. For instance, when a developer wants to edit a product's information, they do not need to edit it manually but simply call a function like editProduct() to edit the information.

### 3. Inheritance
Through inheritance, users can simply reuse a function that is already the base of three codes instead of copy-pasting and modifying each code. For example, when multiple functions in the code both start with a class, instead of copy and pasting the class, we can define it and let other objects inherit the properties of the class.

### 4. Polymorphism
By using polymorphism in this program, the code will run much smoother and faster because of the reduced unreadable codes that stretch for long when it can be shortened into a few lines. For example, when making if-then statements, instead of using these long, redundant string of codes, we can simply use one code that adapts depending on different products.

## Reflection
Among the four pillars, I think that Encapsulation would be the most useful. This is because instead of grabbing the 5 variables one by one in each function, we can simply dissolve these variables into one class. Through Encapsulation, we are able to create concise and efficient code.
